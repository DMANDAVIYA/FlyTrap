HackUMass Labs API

Everything you need to call the platform API: authentication, the resources you can read, and how errors are reported. Inference requests go to each deployment's own URL; this API covers your account, models and billing.

Quickstart

  1. Create an account on the sign-up page. A default API key is issued automatically.
  2. Copy the key from the API keys section of your account dashboard.
  3. Make your first request:
curl https://hackumass-labs.example/api/v1/models \
  -H "Authorization: Bearer $HL_API_KEY"

Or with the Python client:

pip install hlabs

import hlabs
client = hlabs.Client()          # reads HL_API_KEY from the environment
for model in client.models.list():
    print(model.slug, model.size_gb)

Authentication

Every request is authenticated with an API key sent as a bearer token. Keys start with hl_live_ and are scoped; a key can only do what its scopes allow (inference, models:read, models:write, billing:read).

Authorization: Bearer hl_live_<your key>

Keep keys out of source control. Store them in your secret manager or environment. If a key leaks, ask support to rotate it; old keys stop working immediately.

Requests made from the dashboard in your browser use your signed-in session instead of a key.

Errors and limits

Errors use conventional HTTP status codes and a JSON body with a single error field.

HTTP/1.1 403 Forbidden
{"error": "forbidden"}
StatusMeaning
401Missing or invalid API key.
403The key is valid but cannot read this resource. Customers can only read their own records.
404The resource does not exist.
429Rate limited. Default limit is 600 requests per minute per key.

Users

GET/api/v1/users/{id}

Returns the profile of the user that owns the key. Requesting any other user returns 403.

{"id": 1, "email": "dana@valley-robotics.example", "name": "Dana Whitfield",
 "org": "Valley Robotics", "role": "customer",
 "created_at": "2025-09-20T12:00:00", "last_login": "2026-11-13T16:00:00"}

Invoices

GET/api/v1/invoices/{id}

Returns one of your invoices. Amounts are in cents.

{"id": 9001, "user_id": 1, "period": "2026-10", "amount_cents": 18250,
 "currency": "usd", "status": "paid", "created_at": "2026-11-01T09:00:00"}

Fine-tuning

Fine-tuning jobs run on dedicated GPUs and produce a new, versioned model in your private registry. LoRA adapters are available on every plan; full fine-tuning is available on Growth and Scale. Each job ends with an evaluation report comparing the new version with its base model.

hlabs finetune create \
  --base kestrel-13b-instruct \
  --data s3://your-bucket/support-tickets.jsonl \
  --method lora --epochs 3

Deployments

A deployment serves one model version behind a stable HTTPS URL such as support-13b.run.hackumass-labs.example. You choose a GPU class and a replica range; we scale between them based on queue depth and can scale to zero when idle.

Security

Weights and datasets are encrypted at rest and in transit. Staff access to customer resources requires a support ticket and is logged. Scale customers can enable SSO and private networking. Report a security issue through the contact form.
